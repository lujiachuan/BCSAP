# 桌面客户端 UI/UX 审查与界面改造方案

> 版本：v2（可执行版）　评审对象：`apps/desktop_client`（PySide6，浅/深双主题）
>
> 审查依据：源码逐文件审查（main / theme / pages / widgets / initialization / nav_icons / windows_chrome）＋ WCAG 对比度核算 ＋ 离屏渲染截图（`docs/ui-review-snapshots/`）
>
> 设计方向：**专业仪器控制台 · 蓝色视觉体系 · 有边界的亚克力质感 · 克制且可关闭的动效**

---

## 0. 评审结论与执行原则

### 0.1 结论

方案整体可行，建议按本版实施。现有客户端的主题、页面骨架和业务模拟流都适合渐进改造，不需要重写 UI 架构。

原方案需要修正的核心，是把“视觉升级”从大面积玻璃、阴影和动画，调整为以下优先级：

1. **控制可信度与可读性**：连接状态、告警、焦点、对比度和初始化结果必须清晰可靠；
2. **核心数据交互**：扫谱与调束曲线必须具备专业数据图表能力；
3. **一致性与效率**：统一令牌、间距、字号、状态来源和组件行为；
4. **视觉质感**：玻璃、环境光和动效只用于建立层级，不干扰数据阅读和操作。

### 0.2 成功标准

改造后的界面应让用户在 3 秒内回答三个问题：

- 当前数据服务、仪器执行服务和 PV 是否可用；
- 当前是否允许执行扫谱或调束；
- 如果不可用，失败发生在哪里、何时发生、下一步怎么处理。

### 0.3 明确不做

- 不把图表、表格、配置表单和告警区做成高透明玻璃；
- 不承诺 Qt 面板级实时背景模糊；
- 不把自绘无边框标题栏纳入主线交付；
- 不为静止的“正常/就绪”状态增加持续脉冲；
- 不用装饰性动画延迟用户操作或掩盖后台任务；
- 不以“全仓零字面量”为目标，图标绘制、算法参数和局部组件允许通过白名单保留必要常量。

## 1. 现状基线与保留资产

### 1.1 保留资产

| 资产 | 位置 | 处理方式 |
|---|---|---|
| 双主题调色板与 QSS 生成 | `theme.py` | 保留入口，拆分令牌与样式模板 |
| 页面统一骨架 | `pages.py`、`widgets.py` | 在现有 `Panel/PageHeading/MetricCard` 上渐进升级 |
| 矢量导航图标 | `nav_icons.py` | 保留绘制路线，补齐 DPR 与颜色令牌 |
| 扫谱/调束模拟数据流 | Scan/Tuning 页定时器 | 继续作为演示、性能与回归测试数据源 |
| 初始化流程 | `initialization.py` | 保留非阻塞结构，重新定义“可进入”和“后台同步”边界 |
| 窗口与偏好记忆 | `QSettings` | 保留，增加减少动态效果等偏好 |

### 1.2 审查问题重新分级

原方案把“无阴影、无动画”等视觉差异定为高严重度，容易让实施顺序偏离业务风险。本版按影响重新分级：

#### P0：优先修复，影响正确操作、信息可信度或无障碍

| 编号 | 问题 | 证据/现状 | 目标 |
|---|---|---|---|
| U01 | 关键文本对比度不达标 | 深色主按钮白字 3.42:1；浅色侧栏分组字 2.30:1；浅色警告色 3.49:1 | 正文级 ≥4.5:1，大字号/非文本图形 ≥3:1 |
| U02 | 核心曲线能力不足 | 手绘 `LinePlot` 缺少刻度、十字读数、缩放、峰值标注；pyqtgraph 已声明但未使用 | 封装 `SpectrumPlot`，同时区分原始数据与显示数据 |
| U03 | 状态可信度不足 | 设备/PV 状态仅以小圆点或短文本表达，缺少失败对象、原因和时间 | 状态由单一模型驱动，提供摘要、明细、时间戳和重试入口 |
| U04 | 焦点、键盘与 DPI 风险 | focus 边框可能引起尺寸跳动；文本字形图标和 48px 固定画布有兼容风险 | 焦点不改控件几何；键盘全流程可达；图标按 DPR 渲染 |
| U05 | 深色标题栏割裂 | `windows_chrome.py` 已有 DWM 标题栏着色但未接入 | 主线只接入原生标题栏着色；Acrylic/Mica 作为可选增强 |

#### P1：第二优先，影响一致性、效率和维护成本

| 编号 | 问题 | 目标 |
|---|---|---|
| U06 | 卡片/面板/页面主要靠 1px 边框区分 | 建立页面、数据面、浮层三层表面体系 |
| U07 | 圆角、间距、字号缺少系统梯度 | 引入有限令牌，不追求过细档位 |
| U08 | 状态区在主壳、工作台、业务页重复搭建 | 用 `AppStatusModel` 统一状态，用不同视图呈现 |
| U09 | 主题切换遍历全控件 repolish | 顶层重设样式，依赖主题的自绘控件显式刷新 |
| U10 | 表格、滚动条、密集参数缺少读取反馈 | 增加 hover、对齐、命中区和可见焦点 |
| U11 | QSS 结构选择器脆弱 | 页面背景由显式容器/属性控制，不依赖内部层级选择器 |

#### P2：按预算选做，主要提升精致度

| 编号 | 项目 | 决策 |
|---|---|---|
| U12 | 环境光、半透明卡片、轻阴影 | 限定在主壳、Hero、普通卡片和浮层 |
| U13 | 页面淡入、按钮过渡、数值淡换 | 先做关键路径，允许关闭 |
| U14 | 表格整行胶囊圆角、Tooltip 动画、动态阴影 | 默认延期，除非 M3 后仍有预算 |
| U15 | Windows Acrylic/Mica、自绘标题栏 | 独立 POC，不阻塞主线 |

### 1.3 真机必须复核的边界

离屏截图无法替代以下测试：

1. Windows 10/11 的字体、标题栏和系统缩放差异；
2. 100% / 125% / 150% / 200% DPI 下的图标、焦点和命中区；
3. 1366×768 低分辨率下的设置页与业务页布局；
4. 浅色环境下玻璃面的最差对比度；
5. 屏幕阅读器、键盘导航顺序与减少动态效果。

## 2. 目标设计语言与视觉边界

### 2.1 设计语言

> **实验室控制台式现代界面**：数据区域稳定、清晰、低干扰；操作和状态区域用蓝色建立导航与反馈；环境光和半透明只负责层级与空间感。

### 2.2 三层表面体系

| 层级 | 适用区域 | 表现 | 透明度原则 |
|---|---|---|---|
| L0 页面基底 | 主窗口、页面背景 | 低饱和环境光与轻渐变，可缓存 | 不承载正文 |
| L1 数据工作面 | 图表、表格、表单、日志、告警 | 纯色或近乎不透明，边界稳定 | 优先保证对比度与连续阅读 |
| L2 强调/浮层 | Hero、普通信息卡、状态胶囊、菜单、Toast | 半透明填充、1px 高光、轻阴影 | 仅在不影响内容识别时使用 |

玻璃效果默认采用“半透明填充＋环境光背景＋高光描边”的视觉模拟。Qt QSS 不支持真正的面板级实时背景模糊；Windows Acrylic/Mica 仅作为窗口级增强实验，不写入主线验收承诺。

### 2.3 色彩原则

- `accent`：文字、链接、图标和选中描边，正文使用时必须 ≥4.5:1；
- `accentSolid`：主按钮与进度填充，承载白字时必须 ≥4.5:1；
- `accentSoft`：选中底色和弱提示底色；
- `accentGlow`：焦点和环境光，只作为辅助，不承担唯一信息表达；
- `good / warn / error / idle`：颜色必须同时搭配文字或图标，不能只靠颜色区分。

对半透明表面做对比度验收时，应以最亮和最暗背景合成后的最差值为准，而不是只核算 RGBA 前景色。

## 3. 信息架构与状态模型

### 3.1 引入 `AppStatusModel`

新增轻量 `QObject` 状态模型，作为初始化页、侧栏、工作台和业务页的单一状态源。模型只管理状态，不直接操作控件。

建议字段：

| 分组 | 字段示例 | 说明 |
|---|---|---|
| 初始化 | `phase`、`progress`、`is_essential_ready` | 当前阶段、总体进度、是否满足进入主界面的必要条件 |
| 数据服务 | `data_service_state`、`last_sync_at`、`sync_progress`、`sync_error` | 可达性、本地同步进度与失败信息 |
| 仪器服务 | `instrument_state`、`instrument_error` | 仪器执行地址可达性 |
| PV | `pv_total`、`pv_connected`、`pv_failed`、`pv_details` | 汇总与失败 PV 明细 |
| 本地缓存 | `cache_state`、`cache_version`、`cache_path` | 是否可用、当前版本和存储位置 |
| 操作资格 | `can_scan`、`can_tune`、`blocking_reasons` | 由状态推导，页面不自行拼条件 |

模型通过信号发布状态变化，各视图只订阅自己需要的字段：

```text
初始化任务 / 重试操作 / 后台同步
                │
                ▼
         AppStatusModel
        ┌───────┼────────┐
        ▼       ▼        ▼
     初始化页   侧栏      工作台/业务页
```

### 3.2 初始化流程重新定义

进入软件时并行执行：

1. 检查数据服务地址是否可达；
2. 检查仪器执行地址是否可达；
3. 仪器地址可达后，检测全部 PV 连接；
4. 数据服务地址可达后，拉取远端数据到本地；
5. 根据必要条件解锁主界面，非必要的大批量同步继续在后台运行。

关键规则：

- **连通性检查和数据同步分离**：数据服务已可达即可报告成功，不要等全部数据下载完才更新状态；
- **必要检查和后台任务分离**：配置、本地缓存校验、服务/PV 检查属于进入判定；全量或增量数据同步可在主界面继续；
- **允许降级进入**：仪器不可达时仍可进入只读/离线功能；执行扫谱和调束时明确禁用并显示原因；
- **失败可定位**：PV 检查显示“已连接/总数”，失败条目可展开，包含 PV 名称、错误和最后检查时间；
- **取消和重试有边界**：重试单个服务不重复执行所有已成功步骤；后台下载支持取消和断点/增量策略；
- **不要伪造进度**：未知总量使用不确定进度，已知总量才显示百分比。

### 3.3 状态呈现规则

| 状态 | 视觉 | 动效 |
|---|---|---|
| 检查中/连接中/运行中 | 状态点＋动作文本＋可选进度 | 可脉冲，页面不可见时暂停 |
| 正常/就绪 | 稳定图标＋简短文本 | 不持续脉冲 |
| 警告/降级 | 警告图标＋影响说明＋入口 | 默认静态 |
| 错误/阻塞 | 错误图标＋失败原因＋重试 | 不闪烁；告警保持可见直到确认或恢复 |
| 未配置 | 中性图标＋配置入口 | 无动画 |

## 4. 设计系统与 Qt 实现方案

### 4.1 令牌体系 v2

建议新增 `apps/desktop_client/ui_tokens.py`，`theme.py` 负责调色板装配和 QSS 生成。

| 类别 | 建议令牌 | 说明 |
|---|---|---|
| 颜色 | `accent`、`accentSolid`、`accentSoft`、`accentGlow`、`surfaceCanvas`、`surfacePanel`、`surfaceGlass`、`glassStroke`、`glassHighlight`、`ambientA/B/C` | light/dark 分开调参 |
| 语义 | `statusGood`、`statusWarn`、`statusError`、`statusIdle` 及其弱背景色 | 文本、图标、背景成组定义 |
| 圆角 | `radiusControl=8`、`radiusCard=12`、`radiusPanel=16`、`radiusDialog=20` | 控制档位数量 |
| 间距 | `space4/8/12/16/20/24` | 页面边距与组件间距统一取档 |
| 字体 | `caption=11`、`body=13`、`emphasis=14`、`subtitle=16`、`title=20`、`display=26` | 读数使用等宽数字或固定宽度 |
| 动效 | `fast=120ms`、`base=180ms`、`slow=260ms` | 统一缓动曲线 |
| 阴影 | `flat/raised/pop` | 优先缓存的自绘阴影，不批量挂 GraphicsEffect |

验收采用“受控字面量”而不是“一刀切零字面量”：主题色、字号、圆角和通用间距必须来自令牌；绘图算法、图标路径、布局微调需在审查白名单中说明。

### 4.2 Qt 能力边界

| 目标 | 推荐实现 | 是否主线 |
|---|---|---|
| 静态 hover/pressed/focus | QSS 状态选择器 | 是 |
| 按钮颜色平滑过渡 | 仅对少量关键按钮做自绘属性动画 | 可选，不要求所有按钮 |
| 页面切换 | 对目标页使用单实例透明度动画；避免伪造 QWidget transform | 是 |
| 页面位移 | 包装容器的 geometry 动画或自绘偏移，先做 POC | 可选 |
| 卡片阴影 | 缓存阴影纹理或少量静态效果 | 是 |
| 动态卡片阴影 | 需要频繁重绘 | 延期 |
| 表格 hover | QSS/Delegate | 是 |
| 整行胶囊圆角 | 自定义 Delegate 绘制 | 延期 |
| 进度扫光 | 自绘进度组件 | 可选；QSS 本身不能驱动动画 |
| Tooltip 淡入 | 自定义浮层 | 延期 |
| 原生标题栏着色 | 接入 DWM 颜色属性并由主题令牌驱动 | 是 |
| Acrylic/Mica | Windows 版本检测＋独立开关＋失败回退 | POC |

### 4.3 图标与高 DPI

- ☾ / ☀ / ☰ / ● / ○ / ! 等文本字形改为矢量绘制或内置 SVG；
- QPixmap 按目标控件逻辑尺寸乘 `devicePixelRatioF()` 创建物理像素画布，绘制完成后调用 `setDevicePixelRatio()`；
- 不把固定 48px 当作高 DPI 适配；
- 图标状态色从主题令牌取得，并验证 disabled/selected/focus 四态。

### 4.4 可访问性与减少动态效果

- 为可操作控件设置可见焦点，不通过改变边框宽度造成跳动；
- 保证 Tab 顺序符合页面阅读顺序，主流程可只用键盘完成；
- 状态、告警和禁用原因不能只靠颜色表达；
- 增加“减少动态效果”设置；启用后取消循环、位移和扫光，只保留瞬时状态变化；
- 对持续闪烁、快速脉冲和无意义自动播放做硬性禁止。

## 5. 组件与页面改造

### 5.1 主壳与通用组件

| 模块 | 主线改造 | 可选升级 |
|---|---|---|
| 侧栏 | 选中胶囊、左侧强调条、分组字对比度、统一状态摘要 | 折叠图标细节动画 |
| 标题栏 | 接入原生标题栏深浅着色 | Windows Acrylic/Mica；自绘标题栏不在本期 |
| Panel/Card | 按 L1/L2 分为数据面与玻璃卡，统一圆角/描边/内边距 | hover 抬升仅用于可点击卡片 |
| 按钮 | primary/secondary/danger/ghost 四类；四态齐全；focus 不跳动 | 关键按钮颜色过渡、pressed 下沉 |
| 输入与选择 | 聚焦描边、错误文本、足够命中区 | Switch 只用于立即生效的二元设置 |
| Checkbox/Radio | 表单语义继续使用，不一律改 Switch | 自绘外观按需要实施 |
| 表格 | hover、选中、数字右对齐、表头/滚动条双主题 | 胶囊圆角行延期 |
| 数字读数 | 固定宽度/等宽数字，单位和精度稳定 | 80ms 淡换，仅用于低频指标 |
| Badge/Toast | 状态徽标；Toast 只反馈非阻塞结果 | Toast 滑入动画可关闭 |

### 5.2 启动初始化页

- 用清晰步骤展示“本地准备、数据服务、仪器服务、PV、数据同步”；
- 顶部显示总体结论，步骤行显示状态、耗时和错误摘要；
- 数据同步可转入后台后，主按钮改为“进入工作台”，同步状态在侧栏/工作台持续显示；
- 支持“重试失败项”“离线进入”“打开设置”，按钮是否出现由实际失败类型决定；
- 不用一条假百分比覆盖多个不可度量任务。

### 5.3 工作台

- Hero 区只保留当前模式、是否可执行和最重要的下一步操作；
- 服务状态以数据服务、仪器服务、PV、本地缓存四项呈现，点击进入明细；
- 状态卡只显示摘要，详细错误通过抽屉/对话框查看，避免主页堆日志；
- 快捷操作根据 `can_scan/can_tune` 启用，禁用时提供原因；
- 最近实验表增强 hover、时间与状态对齐，保持数据工作面不透明。

### 5.4 扫谱页

用 pyqtgraph 封装 `SpectrumPlot`，接口与业务数据解耦。最低能力：

- 坐标轴、单位、网格、缩放/平移、范围复位；
- 鼠标十字读数，刷新节流至约 30Hz；
- 峰值标注数量受限，避免标签互相覆盖；
- 采集时锁定或受控更新 X 范围，避免自动范围导致画面跳动；
- 原始数据与显示数据分离，导出永远使用原始数据；
- 大数据使用 `clipToView` 与峰值保持型降采样，禁止简单抽点丢失窄峰；
- 高点数模式默认关闭全局抗锯齿，根据点数切换显示质量；
- 图表区使用 L1 稳定背景，实时读数和操作区可使用 L2 卡片。

### 5.5 自动调束页

- 参数配置、运行监控、结果确认保留三步结构，但步骤条主要表达进度，不制造强制向导限制；
- 运行监控显示目标、当前迭代、关键读数和停止入口；
- 数字预留最大格式宽度，避免每秒跳动造成布局抖动；
- 结果用“前/后曲线＋核心指标差异”表达，不只用绿色/红色文字；
- 写回仪器前必须明确显示目标值、风险和确认动作。

### 5.6 系统设置页

- 宽窗口采用左侧分组＋右侧详情；窄窗口退化为顶部下拉/分段导航，避免双侧栏挤压；
- 服务地址提供“测试连接”，反馈包含耗时、结果和错误摘要；
- PV 配置提供数量、校验结果和失败明细；
- 外观设置包含主题和减少动态效果；
- 保存、测试和重置按钮有清晰作用域，避免全局保存误解。

### 5.7 占位页

用模块图标、一句话范围说明和计划能力列表替代空白；不展示虚假可点击控件或虚假进度。

## 6. 动效规范

动效只服务状态变化、层级关系和空间记忆。

| 场景 | 建议参数 | 规则 |
|---|---|---|
| 页面淡入 | 180ms，OutCubic | 单实例，切页时取消上一次动画 |
| 关键按钮状态 | 120ms | 普通按钮可直接使用 QSS 静态状态 |
| 运行/连接状态点 | 1.2s 循环 | 仅 running/connecting；隐藏页暂停 |
| 数字淡换 | 80–120ms | 仅低频指标，高频曲线不做文本动画 |
| Toast | 180–220ms | 不抢焦点，不遮挡关键操作 |
| 进度扫光 | 1.6s | 只用于无法确定总量且任务确实运行时 |

性能守则：不批量挂 `QGraphicsEffect`；动画对象复用并在销毁/切页时停止；优先动画透明度与少量绘制参数，不通过持续布局重排制造位移；关闭动效后功能必须完全等价。

### 7.2 如必须控制在 10–14 人日

保留 M0–M2 核心内容和 M4 必要验收，并削减：

- 表格整行胶囊圆角；
- Tooltip 动画；
- 全量按钮颜色过渡；
- 全套自绘 Switch；
- 页面位移动画，只保留淡入；
- 动态卡片阴影；
- Windows Acrylic/Mica；
- 非关键页错峰入场动画。

不得削减：对比度、焦点/键盘、DPI、状态模型、初始化降级策略、图表基础能力、减少动态效果和性能回归。

## 8. 量化验收标准

### 8.1 功能与状态

- 初始化中数据服务与仪器服务并行检查；仪器可达后检查全部 PV；数据服务可达后启动本地同步；
- 必要条件完成后可进入主界面，后台同步不阻塞主界面；
- 服务/PV 失败时，初始化页、侧栏、工作台与业务页结论一致；
- 扫谱/调束禁用时能看到阻塞原因和恢复入口；
- 单项重试不会无故重复已成功任务。

### 8.2 视觉与无障碍

- 正文对比度 ≥4.5:1，大字号与必要非文本图形 ≥3:1；半透明表面按最差合成背景核算；
- 100% / 125% / 150% / 200% DPI 无模糊图标、文字裁切和点击区域错位；
- 1366×768、1920×1080 和 2560×1440 页面无关键操作被遮挡；
- 仅用键盘可完成初始化处理、页面导航、扫谱参数填写和设置保存；
- 减少动态效果开启后无循环脉冲、扫光和位移动画。

### 8.3 性能与稳定性

- 主题切换目标 <300ms，肉眼无全树逐控件闪烁；
- UI 主线程单次同步工作目标 <50ms，网络、PV 和文件任务不得阻塞 UI 线程；
- 50,000 点、约 14Hz 更新连续运行 10 分钟，交互无明显积压；
- 150,000 点静态曲线可流畅平移和缩放；
- 十字光标读数刷新上限约 30Hz；
- 运行 30 分钟后内存进入稳定区间，无持续线性增长；
- 切页、关闭窗口和取消任务后，不残留运行中的动画、定时器或下载任务。

### 8.4 回归与截图

- 初始化、离线进入、工作台快捷入口、扫谱、调束、设置保存/测试、主题切换、侧栏折叠和窗口记忆全部回归；
- `tools/ui_snapshot.py` 固定窗口尺寸、DPI、主题、字体和模拟数据种子；
- 每阶段保留浅/深主题改前/改后截图，视觉回归失败可定位到具体页面。

## 9. 风险、降级与回滚

| 风险 | 触发条件 | 降级/回滚策略 |
|---|---|---|
| 玻璃面影响阅读 | 最差背景下对比度不足或浅色主题发灰 | 数据面回退为不透明；只保留主壳/浮层玻璃 |
| 阴影或动效影响性能 | 主线程超预算、曲线掉帧、内存持续增长 | 关闭动态阴影与装饰动画；保留静态层级 |
| pyqtgraph 接入不稳定 | 模拟流或真实数据接口回归 | `SpectrumPlot` 保持稳定接口，旧 `LinePlot` 到 M2 验收后再移除 |
| DWM 能力差异 | Windows 版本/远程桌面下属性失败 | 捕获失败并回退系统标题栏，不影响启动 |
| 后台同步量过大 | 下载耗时、磁盘不足或中断 | 增量/断点、可取消、容量预检；保留上次可用缓存 |
| PV 数量较大 | 全量检查拖慢或造成瞬时连接压力 | 限制并发、分批检查、展示已完成计数与失败明细 |
| 真机与离屏截图不一致 | 字体、DPI、DWM 渲染差异 | M0 与 M4 各做一次真机矩阵，不以离屏截图单独验收 |

每个阶段独立提交，禁止把令牌、状态架构、图表和全量页面改造塞进同一提交；增强项失败时应能回退单个组件或功能开关，而不回退业务修复。

## 附录 C：决策清单

1. 采用 L0/L1/L2 三层表面体系，不做全界面玻璃化；
2. 主线采用原生标题栏着色，Acrylic/Mica 仅做可回退 POC；
3. 增加 `AppStatusModel`，统一初始化、服务、PV、缓存和操作资格；
4. 初始化必要检查完成后允许进入，数据同步可在后台继续；
5. 扫谱切换为 pyqtgraph，并明确原始数据/显示数据与大数据性能策略；
6. 状态动效只用于连接中和运行中，正常状态保持静态；
7. 完整估算调整为 14–23 人日；10–14 人日时按 7.2 削减装饰项；
8. 以量化性能、DPI、键盘、对比度和截图回归作为最终验收，不以主观“更漂亮”单独验收。
